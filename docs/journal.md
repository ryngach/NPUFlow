# Журнал експериментів NPUFlow

Хронологічний лабораторний журнал: що зроблено, навіщо, з якими налаштуваннями, що вийшло
і який висновок. Записи лише додаються; помилкові висновки не стираються, а виправляються
новим записом з посиланням на старий. Матеріал для дисертації і статей.

Формат запису:

- **Мета** — питання або гіпотеза.
- **Що зроблено** — команда, конфіг, варіант, коміт git, ID задачі ClearML, середовище.
- **Результат** — числа з посиланням на файл у `results/` або на задачу ClearML.
- **Висновок** — що з цього випливає і яке рішення прийнято.

Позначення: B0 — базова мережа магістерської роботи (0,50 M параметрів, вхід 320×256);
C3 — B0 з одновимірною кореляцією на s16, PixelShuffle замість `full_refine`-згортки,
без позиційного кодування, з ReLU (`bench/variants.yaml: C3_1d_ps_nopos_relu`).
Детальні таблиці і обговорення — у `PLAN.md` і `RESEARCH_PLAN.md` репозиторію EdgeFlowNet.

### 2026-10-01. Швидкість варіантів архітектури на пристрої без навчання

- **Що зроблено:** `bench/speed.py` — експорт ONNX з випадковими вагами, TPU-MLIR 1.25 у docker,
  INT8 (і mixed з BF16), `model_runner --count 30 --enable-timer` на MaixCAM (CV181x).

  Кандидат для навчання — C3.

### 2026-10-01 — 2026-10-02. Де губиться точність при INT8
- **Мета:** знайти, які блоки й які налаштування квантизації відповідають за втрату точності.
- **Що зроблено:** грудневий чекпойнт B0 (`train_out_v1/Phase2_step30000_EMA_best.pth`),
  230 пар (Sintel clean/final, KITTI), емулятор TPU-MLIR. Вирівнювання діапазонів конкатенацій
  (`bench/eqexp.py`), бісекція блоків у BF16 (`bench/bf16_blocks.py`), перебір методів калібрування
  (`bench/calib_sweep.py`), калібрування методом на блок (`bench/hybrid_calib.py`).
- **Результат:** `results/eqexp.jsonl`, `bf16_blocks.jsonl`, `calib_sweep.jsonl`, `hybrid_calib.jsonl`.
  EPE noc Sintel clean: FP32 1,37; INT8 percentile9999 2,91; INT8 KL 2,25. Вирівнювання не допомагає;
  `--we` ламає модель; TPU-MLIR 1.30.2 дає те саме, що 1.25.
- **Висновок:** половина втрати INT8 — метод порогів, а не мережа. У конвертері — `use_kl`.
  QAT відкладено до навчання фінальної архітектури.

### 2026-10-02. Що робить кожна стадія мережі

- **Висновок:** кандидати на спрощення — s32 і `full_refine`; головне обмеження — діапазон руху.

### 2026-10-02. Протокол оцінки і навчальна інфраструктура
- **Протокол оцінки:** оригінальні кадри, ковзне вікно в масштабі навчання, EPE в оригінальних
  пікселях по всіх валідних пікселях. Грудневий чекпойнт за цим протоколом: Sintel clean 3,42,

- **Інфраструктура:** ClearML (хмарний безкоштовний план, проєкт `NPUFlow/train`, черга `kaggle`),

- **Рішення:** працюємо у 320×256 (стандартний протокол на повному кадрі відкладено, `PLAN.md`, розділ 10).

## 2026-10-03. C3 на FlyingChairs, повний прогін (C3-chairs)
- **Мета:** перевірити весь ланцюжок (ClearML, агент Kaggle, продовження з чекпойнта, валідація)
  на повному прогоні; отримати першу точку C3 за протоколом C (Chairs) для порівняння з B0.
- **Що зроблено:** `python kaggle/submit.py --name C3-chairs --config configs/chairs.yaml
  --variant C3_1d_ps_nopos_relu`. Конфіг: Chairs 30 000 кроків, батч 64, lr 2e-3 → 2e-4,
  валідація кожні 5 000 кроків на всьому Sintel train (clean, final) і KITTI-15 train.
  Коміт `3ede691`, задача ClearML `0f75df6b82644704bc3138b7f5301d6f`, поставлена в чергу 2026-10-03.
- **Хід:** агент Kaggle (одна T4, 16 процесів завантаження) взяв задачу о 11:03. Перші 400 кроків —
  0,9 с на крок у середньому: обчислення 0,37–0,46 с, решта — очікування даних з NFS, найбільше
  на межі епох (357 кроків на епоху). Оцінка тривалості: близько 7,5 год плюс валідації.
- **Валідація, крок 5 000** (0,81 год): Sintel clean EPE 10,64 (noc 8,41, Fl 36,0 %), final 10,79
  (noc 8,57, Fl 37,0 %), KITTI-15 EPE 34,62, Fl 73,1 %. Валідація триває близько 5 хв. Після прогріву кешу
  крок 0,58 с, дані майже не чекаються. Для KITTI лоадер читає лише `flow_occ`, тому noc = all.
- **Результат:** завершено, 30 000 кроків за 5,51 год. Валідація EMA-моделі (EPE all / noc / Fl):

  | Крок | Sintel clean | Sintel final | KITTI-15 EPE / Fl |
  |---|---|---|---|
  | 5 000 | 10,64 / 8,41 / 36,0 % | 10,79 / 8,57 / 37,0 % | 34,62 / 73,1 % |
  | 10 000 | 6,20 / 4,34 / 23,5 % | 6,65 / 4,75 / 25,5 % | 25,13 / 59,6 % |
  | 15 000 | 5,61 / 3,86 / 21,6 % | 6,16 / 4,35 / 23,8 % | 23,65 / 59,0 % |
  | 20 000 | 5,43 / 3,71 / 21,0 % | 6,30 / 4,53 / 23,7 % | 23,29 / 58,9 % |
  | 25 000 | 5,40 / 3,69 / 20,7 % | **15,64 / 14,53** / 24,4 % | 23,15 / 58,7 % |
  | 30 000 | 5,27 / 3,57 / 20,4 % | 6,01 / 4,24 / 22,8 % | 23,01 / 58,5 % |

  Чекпойнт `chairs_ema_best` (крок 30 000) і `train_state` — артефакти задачі ClearML.
- **Висновок:**
  - Ланцюжок ClearML + Kaggle працює на повному прогоні без втручання.
  - Крива ще спадає на кінці: 30 000 кроків Chairs для C3 не насичують модель.
  - Аномалія на кроці 25 000: EPE Sintel final стрибнув до 15,6, а Fl майже не змінився (24,4 %).
    Отже, кілька пар дали величезні помилки на малій частці пікселів (вибух передбачення), а не
    загальна деградація. Модель на кроці 30 000 нормальна. Перевірити на збереженому чекпойнті,
    чи бувають такі викиди (EPE по парах, максимум |flow|) — ознака нестабільності, важлива для INT8.
  - Порівняння з B0 — після завершення B0-chairs. На кроці 10 000 вони майже рівні:
    C3 6,20 / 6,65 / 25,1 проти B0 6,11 / 6,80 / 23,7 (Sintel clean, final, KITTI EPE).

## 2026-10-03. Швидкість варіантів зіставлення на s8 (розділ 9 PLAN.md) на MaixCAM
- **Мета:** ціна на пристрої кожного способу додати зіставлення на рівні 1/8 до C3, до навчання.
- **Що зроблено:** `bench/speed.py --tag session3`, випадкові ваги, TPU-MLIR 1.25, INT8 і mixed,
  5 запусків × 30 інференсів, MaixCAM. Попередньо виправлено монтування симлінків `bench/work`,
  `bench/calib` у docker (коміт `9726f10`); перша спроба впала саме на цьому, її записи з `error`
  лишились у `results/speed.jsonl`.
- **Результат** (INT8, мс; приріст відносно C3 = 11,25; усі операції на TPU, `cpu_ops` 0):

  | Варіант | Що додано на s8 | INT8 | mixed | +мс до C3 |
  |---|---|---|---|---|
  | V1d | глобальна dual-1D кореляція (MatMul, 72 кан.) | 13,34 | 13,80 | +2,09 |
  | V1c | V1 без f1 у refine_s8 | 14,23 | 14,68 | +2,98 |
  | V1 | глобальна dual-1D + soft-argmax | 14,65 | 15,11 | +3,40 |
  | A1 | локальна 1D r=4, 18 зсувів | 15,97 | 16,41 | +4,72 |
  | V2 | сепарабельне KPN-зміщення f1, ядро 9+9 | 16,40 | 16,85 | +5,15 |
  | V1b | V1 + локальна 2D r=2, 25 зсувів | 19,50 | 19,96 | +8,25 |
  | V2b | V2 + V1 | 20,01 | 20,48 | +8,76 |
  | V3 | розріджена 2D r=2, дилатації 1,2,4, 75 зсувів | 27,07 | 27,53 | +15,82 |
  | V1_B0 | V1 поверх B0 (не C3) | 32,20 | 43,40 | +3,31 до B0 |

- **Висновок:**
  - Кореляція зсувами на s8 коштує 0,19–0,26 мс на зсув (A1, V1b, V3): кожен зсув — окремі
    Slice + Mul + Reduce. Глобальна dual-1D через MatMul покриває весь кадр (72 кандидати) за 2,1 мс,
    тобто вигідніша за будь-яку локальну.
  - Soft-argmax коштує 1,3 мс (V1 − V1d), прибирання f1 з refine_s8 економить 0,4 мс (V1 − V1c).
  - Прирости адитивні: V2b ≈ V2 + V1 (8,76 проти 8,55), V1 поверх B0 і поверх C3 дає ту саму добавку.
  - Локальна 2D-кореляція поряд із глобальною (V1b) і розріджена (V3) дорогі; їх варто тримати лише
    якщо навчання покаже великий виграш точності. Кандидати для навчання за ціною: V1d, V1, V1c, V2.
